## 大进度（你现在在整盘棋的哪一层）

整座城按学习路线是：环境 → 核心对象 → 规则 → 命令行实验 → 以后才是画面/存档/交通经济。

| 层 | 状态 |
|---|---|
| 环境能编、能测、能跑命令行 | 完成 |
| 路网图层（点、段、车道） | 完成，还粗 |
| 建筑挂在路上，不进全局图 | 完成，还粗 |
| 出行：排队求路 + 局部进出 | 完成，还粗 |
| 事物真的在路上连续开 | 未做（现在是跳路点） |
| 车/人差别、世界每帧转 | 未做 |
| 转向、标志、画面 | 故意后做 |

一句话：**逻辑上已经能「从一端到另一端」；还不是一座会自己转的城。**

## 小进度（最近几刀切了什么）

**刚切完（2026-09-11 工作机）**

1. `TripStarter` 发起出行；建筑不再下指令
2. `RouteEnd` 解绑建筑
3. `Thing.Advance()` 跳逻辑点
4. `ComputeScheduler` 通用分算力（分数 + 虚拟时间）；已取消固定绑核
5. `PathCenter` 收请求排队；计算作业不属于任何人；Scheduler 管中心

**还没切（按会卡住扩展的顺序）**

1. 离路太远的房子也会被挂上；接入会扫全部路段
2. 车道方向和寻路邻接表是两套图，单行以后会对不上
3. 走路是跳点，没有速度、没有每帧走一段距离
4. 路改了，建筑身上的 `segment+t` 不会失效

## 一次出行现在怎么走

```
建筑或路上的点
  → RouteEnd（挂接点 + 进出点）
  → TripStarter 发起
  → PathCenter 排队 → Scheduler 管中心并计算
  → 同一段：只走 t→t
  → 跨段：出门 → 入口 Node → 全局最短路 → 出口 Node → 进门
  → Thing 按步骤往前跳
```

建筑只是地点。路网只是 Node 和 Segment。不要把楼塞进全局图。
