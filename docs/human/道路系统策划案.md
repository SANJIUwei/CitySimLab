# CitySimLab 道路系统策划案

状态：评审稿 · 2026-11-20 · 对应系统 15「道路拓扑、车道与建筑接入」

**目标：让道路既能把车送到目的地，又能决定城市怎样长。** 玩家能用现实经验判断：快速路适合跨城通过，但不是沿街商铺的出入口；支路通行能力有限，却能让街区的门口真正接进路网。设计按现实规则，不设一套原型规则再换掉。本文借鉴中国大陆资料，不代表地图地区已定。

## 道路分类与玩家选择

| 分类轴 | 类型 | 对玩家意味着什么 |
|---|---|---|
| 城市道路功能 | 快速路、主干路、次干路、支路 | 快速路承接远距离通过；主干路组织骨干交通；次干路集散；支路连接街区与沿线用地。道路选择不只是车道多少，还改变能接哪些路、怎样接地块。 |
| 公路工程技术 | 高速公路、一级、二级、三级、四级 | 是城市外交通廊道的技术等级。高速公路不是城市快速路的另一个名字。 |
| 公路在路网中的地位 | 国道、省道、县道、乡道；村道另见农村公路定义 | 标识路线归属和服务层级，不能由编号直接推出道路宽度、限速或是否为高速。 |

采用真实分类作为目录。**单向/双向、车道用途、分隔带、主路/辅路/匝道、桥梁/隧道、限速都另列**，不能用道路名称替代配置。每种可铺设的道路模板须有对应地区和适用条件，记录断面、设计速度、允许连接方式和沿线开口约束。设计速度与法定限速不共用一个值。

## 路如何接、车如何走

### 道路连接与车道

- 铺设时能看见连接点、各向车道、分隔设施和高程。俯视图相交但没有物理连接的两条路，不会自动变成路口。城市快速路的交叉采用立体形式；是否互通取决于实际匝道和连接，而不是俯视相交。依据 R06。
- 是否能沿某段走，由车道方向、交通参与者和限制条件共同决定。设专用车道时按适用类别通行；有时段限制时随当前时段判断。右侧通行不表示整条路单向。依据 R01–R03。
- 转向的合法性取决于**从哪边来、到哪边去**，不能仅凭当前位置是同一个路口就认为全都可转。禁转、掉头条件和车道导向共同决定允许的走法。红灯、让行、前车排队另行判断车辆何时通过，不等于永久禁转。依据 R04–R05。

### 建筑如何接入

- 分开记录建筑门、地块车行开口和道路挂接点。既有 `segment + t` 仍可表示挂在哪段的哪个位置，但不能代表那里自动允许车进出。
- 自动推荐只在符合适用地区开口规则且可实际连通的候选中进行；体现条文要求的道路等级优先、间距、同层或实际连接等条件，再在同等候选中比较距离。玩家能看到被排除的原因，例如“快速路主路不允许直接开口”或“没有符合条件的地块出入口”。
- 同一开口分别定义允许的驶入、驶出动作。若该地块适用右进右出，双向道路仍然双向；限制的是开口动作，对向来车须经合法路线绕行。步行出入口不能当成车行开口，辅路也不自动创建开口。依据 R07–R08。
- 改向、移除道路或封闭开口后，重新验证挂接和出行。没有合法替代路线则显示不可达，不让车辆临时违反规则。

## 玩家反馈与经营联系

- **建路时**：提示拟连接状态、为什么无效，以及是否需要实际的支路、辅路或匝道。不能接不等于不能建；若只是高架跨越，明确提示只是跨越。
- **看路线时**：指出失败来自缺连接、单行反向、禁止转向、车辆类别受限，还是地块没有车行开口。可行但需要等待的情况不显示成永久断路。
- **经营时**：用同一个工厂验证影响。厂门接支路，货车经次干路/主干路或实际匝道上快速通道；厂房离快速路很近也不能就近插入。改变厂门允许的转向，可能增加送货绕行距离，而不是直接影响厂房的生产公式。库存、运输计费和贸易仍由对应系统定义（系统 07、09–11）。

## 验收场景

| 场景 | 预期 |
|---|---|
| 单行 A → B，B 只入不出 | A 到 B 合法且可作为终点；无返路则 B 到 A 不可达。两点在同一段时也不能逆行；有合法绕行则可返回。 |
| 双向主干路，某开口为右进右出 | 同侧按规定进出；对向无法在门口横穿；有合法绕行就绕，没有就提示不可达。 |
| 路口只禁西向进口左转 | 禁令只影响对应来向；其他进路合法转向不受影响。红灯只造成等待。 |
| 公交专用道、普通车道并存 | 公交与普通车辆按适用规则选道；普通车辆不会因路径更短而误走专用道。 |
| 快速路和支路上下跨越 | 不生成隐式互通；只有建成且允许连接的设施才可换路。 |
| 厂房靠快速路主路，附近有合法支路 | 通过合法支路开口，不因主路距离更短而挂错；支路移除后重新验证并提示。 |
| 临两条可接道路，适用规定要求低等级优先 | 尊重等级等条件，不把几何“最近”当成最高优先级。不能接入时说明原因。 |

## 当前原型差距与待拍板

- 现有代码：车道已经记方向，但全局路网仍双向；建筑按距离挂接；同段短路不检查方向；跨段按挂接点靠近的端点选边。以上是原型行为，不是本案规则。
- 算法验收：有向路网和按来向禁转时，合法性由图的实际连接表达；不能把当前面向双向图的 ALT 直接套用。用同一合法规则下的 Dijkstra 对照验证最短代价，包含只入不出的终点和合法绕行。算法不是玩法规则。
- 待拍板：游戏覆盖哪个地区与年代；地块正式接入是否允许玩家手动指定并验证；地图尺度若压缩，如何表达原型工程距离而不改写通行规则。具体车道宽度、坡度、曲率和退距按选定的规范与场景制表，未经核对不填统一数字。地形生成仍搁置。

## 实现记录（2026-11-20）

- 已用合法车道、路口转向及建筑开口构建路线，不再使用上文所述仅按最近节点的旧原型。
- 已接入道路施工预览和二次校验。Godot 演示可从现有路口选点铺设合法的路段，提示缺真实路口、同层快速路冲突及立体跨越；道路中途打断与建立新路口目前需显式构造。
- 单车按时间、配置限速和真实的演示相位前进。无信号机动车路权按明确冲突输入计算，不从道路等级猜优先权。参照[道路交通安全法实施条例第 51、52、53 条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_92d27a3736be4585af2357930349374c.html)；当前没有实时多车冲突探测、完整排队模型或统一世界时钟。
- 游戏的地区、年代、地图工程尺寸仍未定；演示配时和单位换算仅用于展示，没有写成现实全国标准。
