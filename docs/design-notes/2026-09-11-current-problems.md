# 当前逻辑层还没解决的问题

日期：2026-09-11
阅读对象：AI
状态：问题清单，不是实现授权。表现层先不管。

## 已经站住的部分

- 路网图层：Node / Segment / Lane；全局图不当建筑节点。
- 建筑生成时对入口做最近点投影，缓存 `segment + t`，不切段。
- 建筑只发 A/B（`TripCommand`），然后不管。
- 事物排队求路：`Submit` → `Process(budget)` → `ReceiveRoute`。
- 局部判定：同一段走 `t→t`；跨段是出门→t→入口 Node，全局最短路，出口 Node→t→进门。
- 入口 Node 看缓存的 `t`，不看门口直线距离。
- `Length`（几何）和 `Cost`（图权重）已分开。

## 现在的问题

### 1. 事物拿到路线后不会走

`Thing` 只会收 `Trip` 和判定局部种类。没有沿步骤移动、没有当前进度、没有“走到下一个点”。逻辑层还停在“有路线图”，不是“在路上”。

### 2. 路线仍然绑在两栋建筑上

`Trip` 握着 `From` / `To` 建筑。事物以后会从路中间、某个 Node、门口出发，不总是建筑到建筑。现在路上的车不好复用同一份路线对象。

### 3. 车道和图是两套拓扑

段上有 Forward / Reverse 车道，邻接表 `_adj` 却一律双向。单行、转向以后，改车道不改图（或反过来）会对不上。这是早就想避免的“拓扑记两份”。

### 4. 最近点接入会扫全图，也没有“太远就不接”

`AttachNearest` 遍历全部路段，没有半径粗筛。再远也会挂上最近的那一段。城市一大，生成建筑会变慢；离路很远的房子也会被当成已接入。

### 5. 路改了，建筑缓存不会失效

`Attachment` 是生成时写死的。路段移动、删除、拆分之后，旧的 `segment + t` 仍然被寻路当真理。

### 6. 未接入的建筑仍能发出行指令

`IssueTo` 不检查是否已经挂路。事物照样排队，`PlanTrip` 才会抛错。失败发生得太晚。

### 7. Node 到 Node 的求路绕过队列

`Pathfinder.Request(startId, endId)` 仍是同步算出。建筑出行走排队，图上出行不走排队。以后路上的车如果走这条，又会变回“每辆车自己搜”。

### 8. 还没有具体种类，也没有模拟节拍

没有车/人的差别，没有每帧调用 `Process` 的世界循环。Headless 只处理一次队列。转向、标志、限速进 Cost、弯路几何，都还没做；这些本来就可以后做，但上面几条会先卡住扩展。

## 建议的下一刀（等用户点头再写）

1. 事物沿已收路线走一步（逻辑进度，不要表现）。
2. 未接入就不要发出行指令；接入失败要能看出来。
3. 接入加最大距离，太远就不挂。
4. 路线对象不要必须握着建筑。

不要把建筑塞进全局图，也不要给每条车道再造 Node。
